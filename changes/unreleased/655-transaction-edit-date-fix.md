Fixed

- `apps/api`: editing a transaction no longer ignores what it cannot use (`#655`). A field it does not take, `accountId` and ids included, is refused with 400 `unknown_field` naming the field; a field of the wrong type, or a status that is not `pending`, `cleared` or `reconciled`, with 400 `invalid_field`; a body that is not a JSON object with 400 `invalid_body`. Editing or deleting a transaction through an account that does not hold it now answers 404 (deleting used to succeed through any account of the workspace). Creating a transaction or a transfer on a date that does not exist (`2026-02-30`, `2026-02-29`) or is not written `YYYY-MM-DD`, with or without a time (`2026-1-5`, `not-a-date`), is refused with 400 `invalid_date` instead of a server error, and any such date that reaches the database answers 400 `invalid_date` too.
